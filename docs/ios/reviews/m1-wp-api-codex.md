# Codex review: M1 WP API (round 1)

**REQUEST CHANGES**

- **Major — Partial identity headers bypass mismatch detection.** [APIClassifier.swift:40](/Users/richie/code/quickr-worktrees/ios-m1-api/ios/QuickrKit/Sources/QuickrData/API/APIClassifier.swift:40) requires both headers before comparing either. A 404 carrying a different epoch but no server ID becomes an ordinary retry, without stopping the pass, setting `maybe_delivered`, or signalling `epoch_suspect`. This violates sync-protocol §1.4 and outbox §5.2: a present, different header must trigger mismatch handling on any status. **Fix:** compare each available header independently, server first, before applying missing-header fallbacks; allow mismatch evidence to represent partial headers. Test both partial-header permutations across success and error statuses.

- **Major — A precondition rejection can lose its “nothing executed” evidence.** [APIClassifier.swift:54](/Users/richie/code/quickr-worktrees/ios-m1-api/ios/QuickrKit/Sources/QuickrData/API/APIClassifier.swift:54) returns `.identityMismatch(.responseHeaders)` for 409 `epoch_mismatch` when the server header also differs. Consequently, `setsMaybeDelivered` becomes true instead of preserving the pre-claim state. Outbox §5.2 explicitly requires restoration for either precondition rejection. **Fix:** preserve rejection evidence independently of which mismatch takes priority. This combination should signal identity mismatch with `.preconditionRejected`, permitting restoration. Add a combined-mismatch regression test.

- **Minor — Untrusted bodies re-enter interpretation through response helpers.** [APIOutcome.swift:226](/Users/richie/code/quickr-worktrees/ios-m1-api/ios/QuickrKit/Sources/QuickrData/API/APIOutcome.swift:226) extracts JSON `detail` from headerless 401/403/5xx responses; `errorInfo` also decodes bodies from identity/epoch mismatches. Thus the classifier discards the Problem, but presentation/persistence helpers still interpret its raw body. The headerless-403 test explicitly expects this behavior. **Fix:** gate application-body interpretation on matching identity; use status-based fallback messages otherwise and omit untrusted structured error bodies. The spec’s provenance rules justify this departure from the PWA.

- **Minor — Transport tests do not establish the requested delivery/deadline guarantees.** [URLSessionTransportTests.swift:54](/Users/richie/code/quickr-worktrees/ios-m1-api/ios/QuickrKit/Tests/QuickrDataTests/API/URLSessionTransportTests.swift:54) tests a silent server and allows almost five seconds for a 300 ms deadline; cancellation is tested only before sending. **Fix:** add slow-trickle responses to distinguish total deadline from inactivity timeout, cancellation after the server receives a mutation, and connection reset during the response body. Assert prompt completion, underlying cancellation, and `requestStarted == true`.

Otherwise, the base status classification matches the PWA with the specified iOS overrides: undecodable 2xx is uncertain; 404, `entry_deleted`, and `stale_revision` remain distinct; headerless non-2xx never becomes terminal. Request construction covers every operationId, mutation-only Expect headers including APNs, captured expected-identity comparison, CF Access headers, provenance, and encoded query `+`. Redirect refusal, default cache/cookie/credential hygiene, Sendable declarations, and the deadline/cancellation structure look sound by inspection.
