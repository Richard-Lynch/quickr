## Resolution

1. **Fixed.** The monotonic test now holds `performance.now()` by hand (`vi.spyOn(performance, 'now')`) and moves it past the cooldown only after the double tap, so a slow machine can't end the cooldown early. It still runs the app's own clock (no injected one), and still fails when `monotonic` reads `Date.now()` (mutation checked).
2. **Stands.** `settle()` is a fixed wait for a send that must *not* happen, so load can only give a false pass, never a flake; the pattern predates this WP and is shared with the "within one render" tests. The cooldown's decision itself is now deterministic: the second tap of each pair is inside the frozen clock's cooldown and is rejected synchronously in the handler, before anything is enqueued. Each test now first waits for the expected sends (`sent(h, n)`), so the positive half doesn't depend on the 300 ms either.
