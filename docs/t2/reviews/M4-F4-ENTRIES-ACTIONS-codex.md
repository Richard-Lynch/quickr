**Findings**

1. **[P1] Editing can invalidate a queued removal.** [TimingSection.tsx](/Users/richie/code/quickr-worktrees/t2-m4-factions/frontend/src/components/runs/TimingSection.tsx:331) opens the server timing even when a Remove is pending, although the section displays the projected timing. If the user saves before the queued Remove reaches the server, the timing edit can succeed at the unchanged revision, mark the timing edited, and cause the later Remove to be rejected. The user can lose the removal they were shown. Disable editing while removals are pending, or coordinate the edit behind their acknowledgement and open the resulting timing. Add a test covering a queued Remove followed by Edit times.

2. **[P2] The timing editor lacks the specified lap-type picker.** [TimingEditor.tsx](/Users/richie/code/quickr-worktrees/t2-m4-factions/frontend/src/components/runs/TimingEditor.tsx:158) offers only step or Lap; it calculates a cycle label but cannot choose “none” or a declared type as content-display §3.2 requires. The current [TimingEditSegment schema](/Users/richie/code/quickr-worktrees/t2-m4-factions/backend/app/schemas/api.py:471) also has no lap-type field, so this needs an M1-owned contract/model patch as well as the M4 UI, or an explicit spec decision changing the requirement. Test selecting and saving typed and untyped laps.

3. **[P2] OQ-14 filtering is missing from `lastEntry`.** [EntriesPage.tsx](/Users/richie/code/quickr-worktrees/t2-m4-factions/frontend/src/pages/topic/EntriesPage.tsx:383) filters the list and the detail route redirects, but [lastEntryOptions](/Users/richie/code/quickr-worktrees/t2-m4-factions/frontend/src/api/entries.ts:95) still requests one server entry without excluding locally open or finishing runs. Consequently the tile and record form can still use a hidden entry as the latest entry, contrary to timers2 §5.3. Provide a local-runs-aware latest-entry selection that can retrieve the next eligible entry, and test a reopened latest entry with an older entry behind it. Coordinate changes to files owned by another milestone with their owner.

4. **[P2] Filtering can strand pagination.** [EntriesPage.tsx](/Users/richie/code/quickr-worktrees/t2-m4-factions/frontend/src/pages/topic/EntriesPage.tsx:428) selects the empty state when every loaded row is hidden; the load-more control is inside the non-empty branch. If a page contains only hidden entries while another page exists—for example, a filtered result or a small page—the remaining entries cannot be reached. Keep pagination available independently of the visible row count or fetch forward until an eligible row is found. Add a test with a fully hidden first page and a visible second page.

The merge sanity check passed for the requested `getTopicTiming` resolution: the merged backend mapping, schemas, Swift DTO and fake timing contain the M1 `lap_types` fields once, with no duplicate M4 lap-type blocks. Other `T2-M4` blocks remain in shared files for unrelated M4 changes.

The WP’s changed production files are M4-owned entry/timing UI files or the M4-created entry timing helper; I found no direct shared-file or ownership violation in the commit. The missing lap-type contract above requires coordination with M1 rather than a direct M4 edit to its owned model files.
