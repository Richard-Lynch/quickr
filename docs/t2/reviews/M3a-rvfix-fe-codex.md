- **P1 — A slug change can unmount the form before conflict recovery finishes.** [SettingsPage.tsx](/Users/richie/code/quickr-worktrees/t2-m3a-rvfix-fe/frontend/src/pages/topic/SettingsPage.tsx:246) sends the PATCH by ID, but `useUpdateTopicMeta` invalidates active topic queries after every attempt, including a 409. The active `TopicLayout` query still uses the old route slug; if that slug changed elsewhere, its refetch returns 404 and `TopicLayout` renders “Topic not found,” unmounting the form while the retry is in progress. This can lose the edits and prevent the conflict message or navigation from appearing. The new slug-change test misses this because its mock layout continues rendering the outlet even when its query errors.
