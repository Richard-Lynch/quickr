- **P2 — Alerts can still be added after their fire time.** [RunAlertScheduler.swift](/Users/richie/code/quickr-worktrees/t2-m1-gatefix-ios/ios/QuickrKit/Sources/QuickrData/Notifications/RunAlertScheduler.swift:129) samples `due` once, then awaits each `center.add`. If an earlier add suspends until a later desired alert is due, that later alert still passes the stale time check and is scheduled with the system’s one-second minimum delay. The check also excludes requests present in the pending snapshot, even if a mismatched request is delivered before its replacement is added. Both paths can produce a late or duplicate alert, contrary to §9.1 and the P2-2 intent. Check the clock immediately before each add, including replacements; add coverage where an add suspends across another alert’s fire time.
