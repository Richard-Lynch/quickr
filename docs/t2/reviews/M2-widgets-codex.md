1. **P1 — A lap with a pending step shows and sends Next instead of Lap.** [WidgetTopic.swift](/Users/richie/code/quickr-worktrees/t2-m2-widgets/ios/QuickrKit/Sources/QuickrCore/Widgets/WidgetTopic.swift:148) trusts `RunActivityDisplay.buttons.first`, but the current display chooses Next whenever `nextLabel` is present, including while a lap is open. The medium widget therefore advances to the pending step when its primary should record another lap. The typed-lap test overrides `display.buttons` by hand, so it does not exercise the production path.

2. **P1 — The compact Auto rule will stop a run prematurely when the display adopts lap-primary.** [WidgetTopic.swift](/Users/richie/code/quickr-worktrees/t2-m2-widgets/ios/QuickrKit/Sources/QuickrCore/Widgets/WidgetTopic.swift:156) derives untyped Auto solely from the primary. For an untyped lap with a named step still pending, the specified primary is Lap, but Auto must remain Next. This code instead returns Stop; the small widget sends that explicit stop, while the Control displays Stop but sends Auto, which advances. Test that state through both surfaces when adopting the display change.

3. **P1 — Typed timers can never select typed Auto.** [WidgetTopic.swift](/Users/richie/code/quickr-worktrees/t2-m2-widgets/ios/QuickrKit/Sources/QuickrCore/Widgets/WidgetTopic.swift:126) hard-codes `isLapTyped` to false. Once typed timers and their Auto behavior arrive, the small widget can issue Stop where Auto should lap, and the Control can say Stop while its Auto intent laps. The helper tests pass `lapTyped: true` directly and cannot catch the integration failure. The plan explicitly schedules the typed-timer end-to-end test for M2-RESUME, so this dependency must be resolved there at the latest.

4. **P2 — The Timer Control starts a new run instead of opening finishing details.** [TopicControl.swift](/Users/richie/code/quickr-worktrees/t2-m2-widgets/ios/Widgets/TopicControl.swift:179) combines finishing with idle and presents Start with an Auto intent. Spec §5.2 requires “Add details” and an intent that opens the app. A user with an unfinished entry can therefore start another run instead of completing it. The changed test explicitly asserts the contrary behavior.

5. **P2 — The timed widget still omits the required headline and alert.** [WidgetViews.swift](/Users/richie/code/quickr-worktrees/t2-m2-widgets/ios/QuickrKit/Sources/QuickrUI/Widgets/WidgetViews.swift:265) renders the bare label and leaves the alert as a comment. Spec §5.1 requires the headline and, on medium and large widgets, the pending alert line. The comments identify I2-LA-FIELDS as a dependency; that follow-up must actually update this widget, since the current branch does not meet the specified layout.

6. **P2 — The gallery’s lap fixture does not show the layout it claims to cover.** [WidgetGalleryView.swift](/Users/richie/code/quickr-worktrees/t2-m2-widgets/ios/App/Debug/WidgetGalleryView.swift:58) supplies `next: "Rest"` to the current display, which interprets it as Next. Consequently the “lap” gallery shows “Next: Rest,” and its compact version shows Next. Screenshots from this fixture cannot validate the requested lap-primary or typed-lap presentation.

## Resolution (i2-widgets, round 1)

1. **Stands (seam).** `RunActivityDisplay.swift` is I2-LA's file (M2-plan, I2-LA scope; the WP brief: "Do not edit `RunActivityDisplay.swift`; build the widget side on `display.buttons.first` so the §4.1 rule flows through when I2-LA merges"). Today's v1 display rule is the one the widget had before this branch too; the typed-lap test builds the §4.1 display by hand on purpose and says so in its doc comment. Nothing in this branch regresses the pre-I2-LA behaviour; I2-LA makes the production path light up.

2. **Fixed** in `WidgetTopic.autoButton(primary:nextLabel:lapTyped:)`: the untyped (v1) Auto is Next while a named step remains or the steps aren't known, which is "the primary is Next, **or** a lap is open with a step still to come (`nextLabel`)", else Stop. Without lap types a lap's `nextLabel` is never a lap type, so this matches `RunWrites.auto`. `TimedWidgetTests.theSmallSizeFollowsTheOneButtonRule` pins the lap-before-step state on the §4.1 display (compact untyped → `[.next]`, "Next: Out"; typed → `[.lap]`), and the `autoButton` table covers all six inputs. Both surfaces (small widget, Control) read the same function.

3. **Stands (briefed stub).** `TopicTimer.laps` does not exist yet (`QuickrCore/Models/Topic.swift` is M1's); the brief asks for an `isLapTyped` helper that returns false with a `// T2-M1: TopicTimer.laps` comment so the typed branch lights up when M1 lands, and for the typed-timer Control run to happen in M2-RESUME. `theLastStepShowsLapAndStopAndTheSmallSizeStops` pins `isLapTyped == false` with that comment, so M1's landing has to touch this test (the integration marker).

4. **Stands, issue filed:** https://github.com/Richard-Lynch/quickr/issues/132. `RunWidgetIntent` is `supportedModes: .background` and Auto on a finishing run starts a new run; intents are out of this WP's scope ("intents other than the Control's detail text"). A Control labelled "Add details" that starts a run would lie, so the honest v1 "Start" stays, pinned by the test. Also logged as spec friction (§5.2 names an intent that opens the app and, in the same section, "RunWidgetIntent(.auto) unchanged").

5. **Stands (dependency).** `headline` and `alert` arrive with I2-LA-FIELDS (M2-plan; the brief: "No alert line yet: leave the slot in a way that adding it later is one line"). The two `I2-LA-FIELDS:` comments mark the slots; the headline is the label until then (spec §8.2 "before it lands": `headline` falls back to `open.label`).

6. **Fixed:** the gallery now has an untyped lap fixture (`widget.medium.timed.lap`: "Lap" + Stop; `widget.small.timed.auto`: Stop) that shows the lap primary today, and keeps the typed one as `widget.medium.timed.typedlap`, documented as reading "Lap → Rest" once I2-LA lands (I2-UITEST runs after I2-LA, so its screenshots see the §4.1 rendering).
