# Codex review: M2 F2-HOME

## Round 1 (head aac944c8)

1. **[P2] The card does not adapt its controls at large text sizes** — [ActiveTopicCard.tsx:117](/Users/richie/code/quickr-worktrees/t2-m2-fhome/frontend/src/components/topics/ActiveTopicCard.tsx:117), [ActiveTopicCard.tsx:184](/Users/richie/code/quickr-worktrees/t2-m2-fhome/frontend/src/components/topics/ActiveTopicCard.tsx:184)  
   The title row and controls row always remain horizontal. The primary label is truncated and Stop has a fixed width, so increased text size or a narrow viewport can hide the action’s label or crowd the controls. The spec requires the primary and Stop to stack at accessibility sizes, with Pause/Resume moving below the headline.

2. **[P2] Screen-reader traversal puts Pause before the run information and primary action** — [ActiveTopicCard.tsx:130](/Users/richie/code/quickr-worktrees/t2-m2-fhome/frontend/src/components/topics/ActiveTopicCard.tsx:130)  
   DOM order exposes the title link, then Pause/Resume, then the clocks and status, then primary and Stop. The spec calls for the title, headline and clock first, followed by primary, Stop and Pause. A screen-reader user therefore encounters a secondary control before hearing the state needed to understand it.

3. **[P2] The resuming test does not exercise the actual card integration** — [ActiveTopicCard.tsx:71](/Users/richie/code/quickr-worktrees/t2-m2-fhome/frontend/src/components/topics/ActiveTopicCard.tsx:71), [ActiveTopicCard.test.tsx:203](/Users/richie/code/quickr-worktrees/t2-m2-fhome/frontend/src/components/topics/ActiveTopicCard.test.tsx:203)  
   `isResuming` always returns false, while the test passes `resuming={true}` directly. Consequently, the test cannot prove the work package’s queued-reopen behavior: the real `TopicTile` path will never show “Resuming…” or hide controls. The spec permits this fallback until M1 supplies the projection, but the test should make that dependency explicit and cover the integration when it lands.

4. **[P3] Required idle-tile Resume coverage is absent** — [TopicTile.tsx:103](/Users/richie/code/quickr-worktrees/t2-m2-fhome/frontend/src/components/topics/TopicTile.tsx:103)  
   F2-HOME calls for the idle tile’s Resume action and a `TopicTile.test.tsx` covering it. Neither is in the diff. The spec defers the action until M1 supplies `terminal_id`, so this is a dependency gap rather than an independently implementable feature here; it still needs a tracked integration test for the target ID, expiry and optimistic entry once that provider lands.

This was a static review; I did not run the test suite.

## Round 2 (head d550eeaa)

1. **[P2] The card still does not fully adapt at large text sizes** — [ActiveTopicCard.tsx:117](/Users/richie/code/quickr-worktrees/t2-m2-fhome/frontend/src/components/topics/ActiveTopicCard.tsx:117), [ActiveTopicCard.tsx:186](/Users/richie/code/quickr-worktrees/t2-m2-fhome/frontend/src/components/topics/ActiveTopicCard.tsx:186), [ActiveTopicCard.tsx:216](/Users/richie/code/quickr-worktrees/t2-m2-fhome/frontend/src/components/topics/ActiveTopicCard.tsx:216)  
   The controls row can now wrap, but Pause/Resume remains absolutely positioned in the title corner at every text size. The primary label also remains truncated. At large text sizes or with a long step name, users can lose the action’s label; the title is also constrained by permanent right padding. The spec requires Pause/Resume to move below the headline and the primary and Stop to stack at accessibility sizes. The first review’s Dynamic Type finding is therefore only partially resolved.

2. **[P3] The queued-reopen test still does not cover the integration** — [ActiveTopicCard.tsx:71](/Users/richie/code/quickr-worktrees/t2-m2-fhome/frontend/src/components/topics/ActiveTopicCard.tsx:71)  
   `isResuming` always returns false, so the real `TopicTile` path cannot display “Resuming…” or hide controls for an unacknowledged reopen. The spec explicitly permits this fallback until M1 supplies the projection, so it is a dependency gap rather than a demand to invent that projection here. The direct-prop test still cannot verify the integration; it needs a tracked test when the provider lands.

3. **[P3] Required idle-tile Resume coverage remains absent** — [TopicTile.tsx:218](/Users/richie/code/quickr-worktrees/t2-m2-fhome/frontend/src/components/topics/TopicTile.tsx:218)  
   F2-HOME calls for a `TopicTile.test.tsx` covering Resume, including the `terminal_id` target and the expiry window. The spec defers showing Resume until M1 provides `terminal_id`, but there is still no tracked integration coverage for that dependency.

The first review’s screen-reader control-order finding is resolved: the DOM now places primary, Stop, then Pause/Resume after the run information. I found no duplicated controls in the changed card. This was a static review; I did not run the test suite.
