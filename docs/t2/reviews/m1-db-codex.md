Found two correctness issues in the timer schema.

- **P2 — Validation can report a later rule while suppressing an earlier one.** [questions.py](/Users/richie/code/quickr-worktrees/t2-m1-db/backend/app/schemas/questions.py:361) performs duplicate-key and expression checks in an `after` model validator, which Pydantic skips if any nested field fails validation. For example, a timer with two steps keyed `a` and a lap with an empty label reports `laps.0.label` but omits `steps.1.key`. Section 1.3 orders step and lap keys before lap labels. The tests exercise individual rules and multiple field errors, but do not pin this mixed field/cross-field precedence.

- **P2 — Alert expressions are altered before their length and error positions are checked.** [questions.py](/Users/richie/code/quickr-worktrees/t2-m1-db/backend/app/schemas/questions.py:257) inherits `str_strip_whitespace=True` from `StrictModel`. Thus an expression sent as `   x` is evaluated as `x` and reports `unknown_variable at 0` instead of position 3; `1s` followed by 70 spaces is accepted despite exceeding 64 characters. In addition, the `Field` length constraint reports Pydantic’s length message for a 65-character expression, rather than the specified `too_long at 64: …` expression error. [test_timer_schema.py](/Users/richie/code/quickr-worktrees/t2-m1-db/backend/tests/test_timer_schema.py:245) checks the path for long expressions but does not assert the message or whitespace-sensitive positions.
